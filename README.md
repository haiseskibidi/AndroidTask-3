## API

**Название:** Shikimori API
**Ссылка:** `https://shikimori.one/api/doc/1.0`
**Что дает:** Предоставляет информацию об аниме (списки, поиск, детали, рейтинги, постеры).
**Ключ:** Не требуется (Open API).

## Запуск

1. Открыть проект в Android Studio.
2. Дождаться синхронизации Gradle.
3. Запустить на эмуляторе или реальном устройстве (Android 7.0+).
4. Интернет соединение обязательно.

## Домашнее задание 6 (Kotlin Flow)

### Выполнено:
- **Осмысленная реактивная логика:** состояние списка аниме на главном экране (`listUiState`) формируется путем объединения 3 независимых источников:
  - Строка поиска с задержкой ввода (`_searchQuery` с операторами `debounce` и `distinctUntilChanged`).
  - Поток действий пользователя для ручного перезапуска в случае ошибок сети (`_retryTrigger`).
  - Поток избранных аниме из локальной базы данных (`repository.getFavouriteAnimes()`), поставляемый из Data Layer.
- **Мгновенное обновление UI:** при добавлении или удалении аниме из избранного на экране деталей, иконка сердечка на карточке аниме в общем списке обновляется реактивно и без перезагрузки экрана.
- **Рефакторинг репозитория:** из `AnimeRepository` удалены избыточные вызовы `withContext(Dispatchers.IO)`, поскольку suspend-функции в Room и Retrofit нативно выполняются на фоновых потоках и являются main-safe.
- **Валидация тестов:** все тесты успешно пройдены, в тестах ViewModel замокан новый поток избранных аниме из базы данных
