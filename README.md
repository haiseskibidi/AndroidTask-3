## API

**Название:** Shikimori API
**Ссылка:** `https://shikimori.one/api/doc/1.0`
**Что дает:** Предоставляет информацию об аниме (списки, поиск, детали, рейтинги, постеры).
**Ключ:** Не требуется (Open API).

## Запуск

1. Открыть проект в Android Studio.
2. Дождаться синхронизации Gradle.
3. Запустить на эмуляторе или реальном устройстве (Android 7.0+).
4. Интернет соединение обязательно.

## Домашнее задание 5 (Тестирование)

### Выполнено:
- **Юнит-тесты:** 9 тестов.
- **Интеграционные тесты:** 6 тестов.
- **Нетривиальные тесты:** 4 сценария.
- **Flow тесты:** 2 сценария (полная последовательность эмиссий и отмена запросов).

### Покрытые сценарии:

#### Unit-тесты (`app/src/test`):
- **AnimeViewModelTest:**
    - Начальное состояние (`Loading`).
    - Успешный поиск (`Loading` -> `Success`).
    - Обработка ошибок сети (`Error`).
    - Обработка пустого результата (`Empty`).
    - **Нетривиальный:** логика `Retry` инициирует новый вызов репозитория.
    - **Flow/Нетривиальный:** отмена устаревших запросов при быстром вводе (`flatMapLatest`). Проверяется отсутствие "лишних" эмиссий от старых запросов.
- **MapperTest & DtoMapperTest:**
    - Корректное преобразование DTO в Domain.
    - Очистка описания от BB-тегов и лишних скобок (Regex).
    - Маппинг Entity в Domain и обратно.

#### Интеграционные тесты (`app/src/androidTest`):
- **AnimeDaoTest (Room):**
    - Запись и чтение из БД.
    - Удаление из избранного.
    - **Нетривиальный:** отсутствие дублей при повторном добавлении (`OnConflictStrategy.REPLACE`).
- **RepositoryIntegrationTest (Repository + Room):**
    - Проверка связки: метод репозитория `toggleFavourite` корректно меняет состояние в реальной БД.
- **ListScreenTest (UI Integration):**
    - Отображение списка при `Success`.
    - Отображение кнопки `Retry` при `Error`.
    - **Нетривиальный:** клик по элементу списка возвращает корректный ID аниме (List -> Detail contract).

### Тестирование Flow:
1. **Последовательность эмиссий:** В `AnimeViewModelTest` проверяется цепочка `Loading` -> `Empty` (начальный автозапуск) и `Loading` -> `Success` (после поиска).
2. **Отмена запросов:** Тест `rapid query changes` проверяет, что при задержке первого запроса и мгновенном старте второго, результат первого игнорируется, обеспечивая детерминированность UI.
